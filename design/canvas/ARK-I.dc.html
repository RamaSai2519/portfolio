02 — one query, end to end

Seven hops, one reply

  1. User writes on WhatsApp

    The webhook hands the message to Flask.

  2. MainGPT reads the context

    The whole conversation is loaded from MongoDB.

  3. It picks a tool

    A function call names the sub-model it needs.

  4. Controller spins it up

    Fresh, stateless, scoped to this one query.

  5. Sub-model fetches and answers

    Calls its API, returns a structured result, and is gone.

  6. MainGPT writes the reply

    Results are merged into one answer in the user's thread.

  7. Sent back on WhatsApp

    History is saved; Slack hears about anything odd.

03 — the design choice

Why only one model keeps state

stateful · long-lived

MainGPT

Owns the conversation. One place reads and writes history, so context never forks across models.

stateless · one query

Sub-models

Get a small prompt and a schema, call one API, return. Short prompts keep them cheap; adding a skill means adding one module.
